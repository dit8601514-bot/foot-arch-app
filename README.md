# AI Footarch — AI 발 아치(발배뼈 하강) 분석·운동 관리 앱

v2.6.0 · 측정 알고리즘 ALG-2.1.0 · 용도: 개인 건강관리

외부 라이브러리 없이 동작하는 모바일 웹앱(PWA)입니다. 흐름은 다음과 같습니다.

1. 카메라 촬영
2. 파란 스티커 3개 검출
3. P1–P3 기준선과 P2 사이 수직거리 계산
4. 체중부하 전·후 변화량 계산
5. 연구 기준에 따른 분류
6. 운동 중재와 수행 기록
7. 연구자 오차 분석과 보정 모델 관리

> 결과는 선별·자가 관리용 참고 정보입니다. 확정 진단에 쓰지 마세요. 표준 발배뼈 하강 검사(NDT)와 동등하다는 검증은 아직 하지 않았습니다.

## v2.6 AI 오차 보정 + 관리자 서버 분리
### AI 오차 보정(앱 NDT → 임상 NDT 추정)
- **학습 자료:** 같은 사람·같은 발을 앱과 표준 임상 NDT(전문가가 자로 측정)로 함께 잰 짝 자료입니다.
- **특징 9가지(앱이 이미 재는 값):** 앱 NDT, 바닥 기준 하강, 앉은 자세 높이, 아치 각도 변화, 발 길이 변화, 촬영 거리, 발 기울기, 원근 왜곡, 스티커 부착 높이 오차.
- **후보:** 보정 없음 · 평균 차이 · 선형 · 다변량 릿지 회귀. 릿지의 λ는 학습 자료 안에서만 고릅니다(중첩 교차검증).
- **평가:** 참여자 한 명씩 빼고 학습해 그 사람을 예측하는 교차검증(LOPO)으로만 판단합니다.
- **배포 조건:** 보정 없음보다 평균 오차가 10% 이상 줄고, RMSE도 줄고, 참여자 재표집(2,000회)의 95% 하한에서도 개선이 유지될 때만 배포를 권고합니다.
- **모의시험(각 30회):**
  - 앱이 이미 정확한 경우(순수 잡음): 잘못된 배포 권고 **0/30**
  - 앱에 체계적 오차가 있는 경우(12명): 정상적으로 배포 권고 **30/30**
- **사용자 앱 표시:** 결과에 "AI 보정 (임상 NDT 추정)"과 예상 오차(±)를 앱 측정값과 **따로** 표시합니다. 앱 측정값과 분류는 바꾸지 않습니다.
- **코드:** `C.errorFeatures`, `C.trainErrorModel`, `C.applyErrorModel` (단위 테스트 4개).

### 관리자 서버 분리
- **관리자 앱** `/admin/`: 사용자 앱과 별도 페이지이고 로그인 정보도 따로 저장합니다. 사용자 앱에는 관리자 기능 코드가 없습니다.
  - 대시보드, 사용자·측정, 임상 NDT 입력, 오차 분석(Bland–Altman), AI 학습·배포·중지, 가명 CSV 내보내기
- **권한은 서버가 판단합니다**(`supabase/admin.sql`). 관리자 지정은 SQL Editor에서만 할 수 있습니다.
  - 관리자는 연구 활용 동의자의 기록만 읽을 수 있고, 미동의자는 통계에만 포함됩니다.
  - 일반 사용자는 모델을 올릴 수 없습니다.
- **동기화:** 사용자 앱은 본인 기록만 내려받습니다(`user_id=eq.<본인>`).
- **테스트:** `node test/e2e-admin.js` (모의 서버로 19개 검증)
  - 서버 규칙: 본인만, 관리자는 동의자만, 미동의자 기준값 거부, 일반 사용자의 모델 업로드 거부
  - 관리자 앱: 비관리자 거부, 통계·목록·전화번호 가림, 기준값 입력, 오차 분석, 학습·배포·중지
  - 사용자 앱: 세션 분리, 본인 기록만, 카메라로 측정한 결과에 AI 보정 표시
- **주의:** `admin.sql`은 실제 PostgreSQL에서 실행해 보지 못했습니다(모의 서버로만 같은 규칙을 검증). 처음 실행할 때 오류가 나면 메시지를 알려 주세요.

## v2.4 기본 측정 방법: 버튼 → 가이드 맞추면 앉은 자세 → 일어서서 10초 후 선 자세
1. **촬영 버튼**을 누르면 10초 타이머가 시작됩니다("10초 뒤에 시작합니다"). 그동안 휴대폰을 두 발 사이에 놓고 앉습니다.
2. **가이드에 맞추면 촬영:** 음성에 따라 발을 윤곽에 맞추고, 윤곽이 초록색이 되면 "발이 정확히 들어왔습니다 → 앉은 자세를 촬영합니다" 후 자동으로 찍습니다.
3. **일어서기:** "이제 그대로 일어서서, 양발에 체중을 똑같이 실어 주십시오. 10초 뒤에 체중부하 사진을 찍습니다" 안내 후 10초 타이머(삑 소리, 마지막 3초는 높은 음)가 지나면 선 자세를 찍습니다.
   - 스티커가 안 보이거나 휴대폰이 움직였으면 이유를 말하며 기다렸다가 찍습니다.
   - 발 모양 변화로 체중부하가 확인되면 "체중부하 확인했습니다. 촬영합니다", 아니면 "체중부하 사진을 촬영합니다"라고 말합니다. 확인 여부는 기록에 남습니다.
- 측정 화면에서 **선 자세 촬영** 방식을 고를 수 있습니다. 기본은 **타이머**이고, **AI 자동 인지**를 고르면 예전처럼 일어서는 동작과 발 모양 변화를 확인한 뒤 찍습니다.
- **테스트:** `test/e2e-self.js` M(타이머 방식), MR(타이머 + 가로로 눕힌 휴대폰). 기존 시나리오는 AI 방식으로 계속 검증합니다.

## v2.3.1 휴대폰 흔들림과 발 움직임 구분
- **문제:** 예전에는 스티커 점이 화면에서 움직인 거리만 보고 판정해서, 휴대폰이 살짝 흔들려도 "발이 움직이고 있습니다"로 막혔습니다.
- **수정:** 움직임을 둘로 나눠 판정합니다.
  - **형태 변화**(세 점의 상대 배치, `C.shapeDelta`)는 발이 실제로 움직인 것입니다. 스티커 지름의 0.12배를 넘으면 촬영을 보류합니다.
  - **세 점이 함께 이동**하는 것은 휴대폰 흔들림입니다. 측정값이 상대 배치라 영향이 거의 없으므로 크게 흔들릴 때만(0.8배 초과) 보류하고, "휴대폰이 흔들리고 있습니다"라고 안내합니다. 흐림은 선명도 검사가 따로 잡습니다.
  - 연속 촬영을 결합할 때 프레임마다 P1·P3 중점 기준으로 바닥선 높이를 재므로, 촬영 중 흔들려도 바닥 기준 값이 변하지 않습니다.
- **테스트:** `test/e2e-self.js` H — 휴대폰이 계속 ±5px·±0.4° 흔들리는 영상입니다. 이전 버전은 촬영이 안 되고, 수정 버전은 8.0 mm로 정상 진행합니다.

## v2.3 시안 디자인 · 적응형 발 가이드 · 전문가용 추적 표시 · 스티커 16 mm
- **스티커 지름 기본값 16 mm:** mm 환산을 이 지름으로 바로 합니다. 설정에서 바꿀 수 있고, 테스트 시트 검증을 통과하면 "시트 검증"으로 표시됩니다.
- **적응형 발 가이드:**
  - 스티커가 보이면 표준 발 윤곽(Nielsen 2009 부착 기준)을 실제 발에 맞춰 놓습니다(이동·확대·회전).
  - 판정 기준은 뒤꿈치~앞발 접지부가 화면 안, 크기 적당(P1–P3 폭이 화면의 30~80%), 축 수평 ±10°, P2가 발배뼈 범위인지입니다.
  - 휴대폰과 발의 거리가 달라도 맞출 수 있습니다. 고정 목표 원 방식은 `{ mode: 'fixed' }`로 씁니다.
- **추적 표시:** 스티커마다 잠금 조준선, 실시간 P2 높이(mm), 추적 상태 막대(고정/추적 중/찾는 중·fps·피팅 잔차)를 보여 줍니다.
- **카메라 전환:** 후면 카메라를 순환합니다(아이폰 0.5× 울트라 와이드 포함).
- **선 자세 음성:**
  - 일어나지 않으면 8초마다 다시 안내합니다.
  - 움직임이 작아도 발 모양 변화로 체중부하를 인지합니다.
  - 스티커가 안 보이거나 휴대폰이 움직이면 이유를 말합니다.
  - iOS에서 말하는 중이 아닐 때 cancel하지 않습니다.
- **디자인:** 시안처럼 파란 그라데이션 배경, 투명 머리 영역, 흰 메뉴 버튼을 썼습니다.
  - 측정 화면: 모서리 괄호 틀과 둥근 셔터 버튼
  - 휴대폰 가로 화면에서는 카메라가 한눈에 들어오게 줄입니다.
- **테스트 시트:** 16 mm 스티커로 다시 만들었습니다. 앱 검출 결과는 하강 8.01 mm(정답 8.0 mm)입니다.

- **족궁재활영상:** 썸네일·영상 길이가 있는 카드 목록. 등록되지 않은 영상은 "영상 등록 필요"로 표시합니다.

## v1.5 전문가용 표준 발 가이드와 바닥 기준 NDT

### 표준 부착 위치
Nielsen 등(2009, *J Foot Ankle Res* 2:12)의 3마커 방법을 따릅니다.

- **P3:** 발꿈치뼈 안쪽, 바닥에서 2 cm 위, 발꿈치 뒤끝에서 4 cm 앞
- **P1:** 제1중족골두 안쪽, 바닥에서 2 cm 위
- **P2:** 발배뼈 결절
- 앱의 기본 측정(P2와 P1–P3 기준선 사이 수직거리)은 이 논문의 정의와 같습니다.
- 스티커 부착 화면에서 실제 크기로 인쇄하는 **부착 자(SVG)**를 내려받을 수 있습니다.

### 카메라 가이드 (화면과 판정이 같은 기하 `C.guideGeometry`)
- **화면 구성:** 표준 발 모델(안쪽 면 윤곽, 바닥선, 안쪽 복사뼈 위치)을 화면에 그리고, P3·P1 목표 원과 P2(발배뼈) 범위를 표시합니다.
- **촬영 조건:** P3·P1이 각자의 원 안에 있고, P2가 발배뼈 범위(축 방향 18–62%, 바닥 위 1.8–6.5 cm) 안에 있어야 촬영합니다.
- **음성 코칭:** 벗어나면 거리 → 앞뒤 → 높이 순서로 안내하고, 각 원은 초록/노랑으로 바뀝니다.

### 바닥선(발바닥 경계) 검출
1. 발꿈치와 앞발 아래 세로줄 18개를 훑어, 색 변화가 가장 큰 위치를 포물선 보간으로 찾습니다(서브픽셀).
2. 찾은 점들에 Tukey 가중 직선을 맞춥니다.
3. 오검출 방지 검사를 거칩니다:
   - 스티커 아래가 피부인지
   - 경계 위가 피부이고 아래가 다른 색인지
   - 잔차가 작은지
   - 바닥선 기울기가 12° 이내인지
4. 결과로 **바닥 기준 발배뼈 높이·하강(표준 NDT 방식)**과 **P1·P3 부착 높이 점검(표준 20 mm)**을 계산합니다.
5. 분류에 쓸 값은 연구자 설정에서 고릅니다: P1–P3 기준선(기본) 또는 바닥 기준. 두 값은 항상 함께 기록됩니다.

| 합성 벤치마크 (보류 세트) | 바닥선 검출률 | 바닥 높이 오차 중앙 / 95% |
| --- | --- | --- |
| 표준 부착 · 기본 | 100% | 0.07 / 0.13 px |
| 표준 부착 · 노란 저조도 | 80% | 0.07 / 0.18 px |
| 표준 부착 · JPEG·음영 | 70% | 0.10 / 0.20 px |
| 표준 부착 · 기울기·광택 | 100% | 0.06 / 0.28 px |

- 바닥선을 찾지 못하면 이유를 기록하고 기준선 방식으로 측정합니다.
- 잘못된 바닥선을 받아들인 경우는 0건이었습니다. 스티커가 바닥에 너무 가까운 비표준 배치에서는 의도적으로 거부합니다.

## v1.4 정밀 정렬과 체중부하 인지

### 정밀 정렬
촬영은 세 스티커가 **목표 영역에 정확히** 들어왔을 때만 합니다.

- 조건: 무게중심이 화면 가운데 영역에 있고, P1–P3 길이가 화면 폭의 45–85%, 발 축 기울기 10° 이내, 스티커가 정면으로 보일 것
- 벗어나면 방향을 음성으로 알려 줍니다. 예: "발을 조금 앞으로 옮겨 주십시오", "휴대폰을 조금 더 멀리 두십시오". 앞·뒤 방향은 발가락 방향을 고려해 정합니다.

### 체중부하 인지
다음 순서로 근거를 쌓습니다.

1. **일어서는 동작:** 장면 전체 움직임(축소 영상의 프레임 간 차이)이 커지거나 스티커 추적이 끊기면 인지합니다.
2. **선 자세 안정:** 다시 목표 영역 안에서 1.5초간 안정되어야 합니다.
3. **형태 근거:** 앉은 자세와 비교해 다음 중 하나를 만족해야 합니다. 스티커 지름으로 나눠 비교하므로 촬영 거리와 무관합니다.
   - 아치 하강 ≥ 0.12 × 스티커 지름
   - 발 길이 증가 ≥ 0.6%

세 근거가 모두 갖춰지면 **"체중부하 확인했습니다. 촬영합니다."**라고 말하고 촬영합니다.

형태 변화가 작으면(정상 아치 등) 한 번 더 체중을 실으라고 안내합니다. 그래도 변화가 작으면 "현재 자세로 체중부하 상태를 촬영합니다"라고 말하고, 결과에 **"형태 변화 작음"**으로 기록합니다. 확인되지 않은 것을 확인했다고 말하지 않습니다.

형태 근거 기준값은 초기 추정치이므로 실제 측정 자료로 조정해야 합니다.

### 음성 안내 순서
1. "검사를 시작합니다. 의자에 앉아 체중을 빼고 … 가이드에 들어오게 해 주십시오."
2. (정렬이 맞지 않으면 방향 안내)
3. "발이 가이드에 정확히 들어왔습니다. 움직이지 마십시오."
4. "비체중부하 상태를 촬영합니다." → "촬영되었습니다."
5. "이제 일어서서 체중부하 해주십시오. 양발에 체중을 고르게 실어 주십시오."
6. "일어서는 동작을 확인했습니다. 가만히 서 계십시오."
7. **"체중부하 확인했습니다. 촬영합니다."** → "촬영되었습니다."
8. "검사가 끝났습니다. 결과를 확인해 주십시오."

## v1.3 스티커 검출·추적 엔진 ALG-2.0

### 검출 단계
1. **조명 불변 파란 정도 지표**
   - 계산식: `o = (B − (R+G)/2) / (밝기 + 10)`
   - 밝기로 나누므로 어둡거나 밝아도, 색온도가 바뀌어도 스티커가 배경보다 높은 값을 유지합니다.
2. **적응형 히스테리시스 이진화**
   - 영상 전체 지표의 중앙값과 MAD로 배경 수준을 추정합니다.
   - 강한 임계값을 넘는 픽셀을 씨앗으로 삼아, 약한 임계값까지만 영역을 넓힙니다.
3. **구멍 메움**
   - 광택 반사로 생긴 스티커 안쪽의 흰 점을 메웁니다.
4. **서브픽셀 타원 피팅**
   - 각 후보에서 방사선 64개를 그어 가장자리를 찾습니다.
   - 가장자리는 바깥에서 안쪽으로 탐색하므로 내부 반사에 속지 않습니다.
   - 타원(중심, 장·단축, 각도)은 Huber → Tukey 가중 반복 가우스–뉴턴으로 맞춥니다.
   - 가장자리 점의 각도 공백·피복률·잔차로 가림이나 겹침을 판정합니다.
5. **흐림 판정**
   - 가장자리 10–90% 전이 폭으로 판정합니다.
   - 카메라 영상의 색 해상도(4:2:0)를 고려한 기준입니다. 측정 정확도를 해치는 심한 흐림만 거부합니다.

### 추적 단계
- **칼만 필터:** 기준점마다 등속 모델 칼만 필터를 둡니다. 예측 위치로 탐색 영역(ROI), 후보 대응, 라벨 확인을 하고 움직임 속도를 추정합니다.
- **예측 기반 대응:** 화면에 파란 방해물이 나타나도 예측과 맞는 3개만 고릅니다. 맞는 조합이 없으면 측정하지 않습니다.
- **적응형 색 모델:** 직전에 검출한 스티커의 색 수준으로 임계값을 조정해, 조명이 바뀌어도 추적을 유지합니다.
- **연속 촬영 결합:** 피팅 잔차로 가중 평균합니다.

### 합성 벤치마크 (`bench/`)

17개 가혹 조건을 다룹니다: 노이즈, 색온도, 저조도, 음영, 광택, 기울기, 초점 흐림, 움직임 흐림, JPEG, 데님, 작은 스티커, 복합. 그중 3개 조건(가림, 파란 방해물, 심한 흐림)은 측정을 거부해야 하는 조건입니다.

| 데이터 | 알고리즘 | 성공률 | 잘못된 수용 | 중심 오차 중앙 / 95% | P2 높이 오차 중앙 / 95% |
| --- | --- | --- | --- | --- | --- |
| 개발용 (180장) | ALG-1.1 | 38.2% | 0 | — | — |
| 개발용 (180장) | **ALG-2.0** | **100%** | **0** | 0.06 / 0.80 px | 0.04 / 0.19 px |
| 보류 검증 (180장, 다른 시드) | ALG-1.1 | 41.7% | 0 | 0.03 / 0.76 px | 0.02 / 0.24 px |

- 기존 엔진(ALG-1.1)이 실패한 원인은 대부분 흐림 판정 오류였습니다.
- 보류 검증 세트는 튜닝에 쓰지 않았습니다.

- **한계:** 모두 합성 영상입니다. 실제 발 사진에서는 피부 질감, 스티커 재질, 카메라 처리 방식이 달라 성능이 다를 수 있습니다. 실제 사진에 정답 좌표를 표시한 회귀 세트가 필요합니다.

## v1.2 음성 안내 자가 검사 (손대지 않는 촬영)

1. 휴대폰을 **가로로 세워 두 발 사이 바닥**에 두고, 뒷면 카메라가 검사할 발 안쪽을 향하게 합니다.
2. 시작을 누르면 음성 안내가 나옵니다. 발이 가이드(점선) 안에 1초 동안 안정적으로 들어오면 **“찍습니다”** 하고 **앉은 자세(비체중부하)**를 연속 촬영합니다.
3. “일어서세요” 안내 뒤 일어서는 움직임을 감지하고, 다시 1.5초 동안 안정되면 **“찍습니다”** 하고 **선 자세(체중부하)**를 찍습니다.
4. 전·후 스티커 크기로 휴대폰이 움직였는지 확인합니다. 움직였으면 처음부터 다시 찍습니다.
5. 양발 모드에서는 왼발이 끝나면 휴대폰을 돌려 오른발을 이어서 검사합니다.

결과 화면의 **유연성 평발 자가 확인**은 다음을 보여 줍니다.

- 앉음 → 섬 아치 높이와 하강량
- 연구 기준 분류와 유연성 평발 양상 안내
- 자가 확인 질문 2개(쉴 때도 아치가 없음, 통증·붓기): 하나라도 해당하면 이 검사로는 판단할 수 없어 전문가 상담을 안내합니다.

**관리** 탭에서는 발별 하강량 추이, 운동 횟수, 측정 오차를 고려한 변화 해석을 봅니다.

음성은 Web Speech API(ko-KR)를 씁니다. 음성을 지원하지 않는 브라우저에서는 화면 자막과 신호음으로 대신합니다.

## v1.1 트래킹 개선

- **Web Worker 분석:** 검출을 화면과 분리된 스레드에서 실행합니다. 지원하지 않는 환경에서는 메인 스레드로 자동 전환합니다.
- **ROI 추적:** 직전 프레임에서 찾은 스티커 주변만 검색하고, 놓치면 전체를 다시 검색합니다. 분석 속도가 약 3fps에서 약 15fps로 빨라졌습니다(테스트 환경 기준).
- **라벨 일관성 검사:** 프레임 사이에 P1·P2·P3가 뒤바뀌면 준비 상태를 해제합니다.
- **움직임 판정:** 최근 0.6초 동안 기준점의 최대 이동량(스티커 지름 대비)으로 판단합니다.
- **화면 떨림 보정:** 오버레이 표시만 부드럽게 하고, 측정에는 원래 좌표를 씁니다.
- **연속 촬영(버스트):** 12프레임을 찍은 뒤 흐린 프레임과 튀는 프레임(중앙값 ± 3·MAD)을 버리고, 남은 프레임의 좌표를 평균합니다. 사용한 프레임 수와 높이 SD(반복성)를 함께 기록합니다.

## 연구자 초기 설정

1. 설정 → 연구자·관리자 모드에서 PIN을 설정합니다.
2. 측정 알고리즘 보정 화면에서 스티커의 실제 지름(mm)을 저장합니다.
3. 템플릿을 100% 크기로 인쇄해 촬영하고, 검증을 통과시킵니다. 통과해야 mm 값과 분류가 표시됩니다.
4. 운동 콘텐츠 관리 화면에서 처방 수치와 영상을 입력하고, 분류별로 운동을 연결합니다.

## 개발과 테스트

```
node build.js            # src/ + public/ → dist/ (index.html, sw.js, manifest, icons)
node test/unit.test.js   # 단위 테스트 75개 (CI에서도 실행)
node test/e2e-account.js # 서버 계정 E2E 16개 (모의 Supabase)
node test/e2e-admin.js   # 관리자 앱·AI 보정 E2E 19개 (모의 Supabase)
node test/e2e.js         # 브라우저 E2E 24개 (Playwright, 가상 카메라 영상 필요)
node test/e2e-self.js    # 음성 자가 검사·체중부하 인지·바닥 기준 NDT E2E 42개 (3개 시나리오)
node test/e2e-track.js   # 트래킹 강건성 E2E 6개 (방해물 등장·저조도 전환 가상 영상)
```

단위 테스트는 분류 경계값, 기하 계산, 합성 이미지 검출, mm 환산, 오차 지표, 보정, 트래킹을 다룹니다.

E2E 테스트를 돌리려면 먼저 가상 카메라 영상을 만드세요.

```
ffmpeg -loop 1 -i test/img/pre.png -t 4 -r 10 -pix_fmt yuv420p test/img/pre.y4m
cd test/img && ffmpeg -loop 1 -t 14 -i pre.png -loop 1 -t 2 -i nostickers.png -loop 1 -t 24 -i post.png \
  -filter_complex "[0:v][1:v][2:v]concat=n=3:v=1:a=0,fps=10,format=yuv420p" self.y4m
# self_nochange.y4m: 위와 같되 마지막 영상을 pre.png로
# self_std.y4m: std_pre.png 14초 → nostickers.png 2초 → std_post.png 24초 (표준 부착·표준 발 윤곽 장면)
# track.y4m: pre.png 4초 → pre_distractor.png 4초 → pre_distractor_dim.png 8초 (같은 방식으로 연결)
```

합성 이미지는 테스트 전용이며, 실제 측정 결과와 섞이지 않습니다.

## 파일 구조

```
src/core.js          측정 핵심 로직 (순수 함수, Node·브라우저·Worker 공용)
src/app-base.js      저장소(IndexedDB), 라우터, 아이콘, 검출 실행기(Worker), 차트, PWA 등록
src/app-account.js   서버 계정(Supabase Auth·REST), 로그인·회원가입 화면, 동기화
src/app-design.js    기록보기 달력, 족궁재활영상, 분석 중 화면
supabase/            서버 스키마(RLS)·관리자 서버(admin.sql)와 연결 안내
src/admin.html·admin.js  관리자 앱(/admin, 사용자 앱과 분리)
public/config.js     서버 주소·공개 키 설정
src/app-live.js      음성 안내, 실시간 트래킹, 연속 촬영(공용)
src/app-self.js      음성 자가 검사, 유연성 평발 자가 확인, 관리 현황
src/app-user.js      사용자 화면 (안내, 촬영·트래킹, 분석, 결과, 운동, 이력)
src/app-research.js  연구자 화면 (오차 분석, 보정, 모델, 콘텐츠, 데이터)
public/              manifest, 서비스 워커, 아이콘
.github/workflows/   테스트 → 빌드 → GitHub Pages 배포
```

## 아직 남은 한계

- 실제 발 사진으로 정확도를 검증하지 않았습니다. 검출 기준값은 초기 추정치입니다.
- 데이터는 기기 안(IndexedDB)에만 저장됩니다. 클라우드 동기화 기능은 없습니다.
- NDT 기준의 바닥선 측정과 NDT 하강량 입력 화면은 다음 단계에서 구현할 예정입니다.
- 유연성 평발 판단은 본 연구 분류 기준을 따른 것이며, 경직성 평발은 자가 확인 질문으로만 걸러 냅니다.
