# AI 발 기능 평가 · 평발 운동 중재 앱

v1.3.0 · 측정 알고리즘 ALG-2.0.0 · 용도: 개인 건강관리

외부 라이브러리 없이 동작하는 모바일 웹앱(PWA)입니다. 흐름은 다음과 같습니다.

1. 카메라 촬영
2. 파란 스티커 3개 검출
3. P1–P3 기준선과 P2 사이 수직거리 계산
4. 체중부하 전·후 변화량 계산
5. 연구 기준에 따른 분류
6. 운동 중재와 수행 기록
7. 연구자 오차 분석과 보정 모델 관리

> 결과는 선별·자가 관리용 참고 정보입니다. 확정 진단에 쓰지 마세요. 표준 발배뼈 하강 검사(NDT)와 동등하다는 검증은 아직 하지 않았습니다.

## v1.3 스티커 검출·추적 엔진 ALG-2.0

### 검출 단계
1. **조명 불변 파란 정도 지표**
   - 계산식: `o = (B − (R+G)/2) / (밝기 + 10)`
   - 밝기로 나누므로 어둡거나 밝아도, 색온도가 바뀌어도 스티커가 배경보다 높은 값을 유지합니다.
2. **적응형 히스테리시스 이진화**
   - 영상 전체 지표의 중앙값과 MAD로 배경 수준을 추정합니다.
   - 강한 임계값을 넘는 픽셀을 씨앗으로 삼아, 약한 임계값까지만 영역을 넓힙니다.
3. **구멍 메움**
   - 광택 반사로 생긴 스티커 안쪽의 흰 점을 메웁니다.
4. **서브픽셀 타원 피팅**
   - 각 후보에서 방사선 64개를 그어 가장자리를 찾습니다.
   - 가장자리는 바깥에서 안쪽으로 탐색하므로 내부 반사에 속지 않습니다.
   - 타원(중심, 장·단축, 각도)은 Huber → Tukey 가중 반복 가우스–뉴턴으로 맞춥니다.
   - 가장자리 점의 각도 공백·피복률·잔차로 가림이나 겹침을 판정합니다.
5. **흐림 판정**
   - 가장자리 10–90% 전이 폭으로 판정합니다.
   - 카메라 영상의 색 해상도(4:2:0)를 고려한 기준입니다. 측정 정확도를 해치는 심한 흐림만 거부합니다.

### 추적 단계
- **칼만 필터:** 기준점마다 등속 모델 칼만 필터를 둡니다. 예측 위치로 탐색 영역(ROI), 후보 대응, 라벨 확인을 하고 움직임 속도를 추정합니다.
- **예측 기반 대응:** 화면에 파란 방해물이 나타나도 예측과 맞는 3개만 고릅니다. 맞는 조합이 없으면 측정하지 않습니다.
- **적응형 색 모델:** 직전에 검출한 스티커의 색 수준으로 임계값을 조정해, 조명이 바뀌어도 추적을 유지합니다.
- **연속 촬영 결합:** 피팅 잔차로 가중 평균합니다.

### 합성 벤치마크 (`bench/`)

17개 가혹 조건을 다룹니다: 노이즈, 색온도, 저조도, 음영, 광택, 기울기, 초점 흐림, 움직임 흐림, JPEG, 데님, 작은 스티커, 복합. 그중 3개 조건(가림, 파란 방해물, 심한 흐림)은 측정을 거부해야 하는 조건입니다.

| 데이터 | 알고리즘 | 성공률 | 잘못된 수용 | 중심 오차 중앙 / 95% | P2 높이 오차 중앙 / 95% |
| --- | --- | --- | --- | --- | --- |
| 개발용 (180장) | ALG-1.1 | 38.2% | 0 | — | — |
| 개발용 (180장) | **ALG-2.0** | **100%** | **0** | 0.06 / 0.80 px | 0.04 / 0.19 px |
| 보류 검증 (180장, 다른 시드) | ALG-1.1 | 41.7% | 0 | 0.03 / 0.76 px | 0.02 / 0.24 px |
| 보류 검증 (180장, 다른 시드) | **ALG-2.0** | **100%** | **0** | 0.06 / 0.68 px | 0.04 / 0.24 px |

- 기존 엔진(ALG-1.1)이 실패한 원인은 대부분 흐림 판정 오류였습니다.
- 보류 검증 세트는 튜닝에 쓰지 않았습니다.
- CI에서 매번 별도 시드로 벤치마크를 돌립니다. 성공률 97% 이상, 잘못된 수용 0건, 높이 오차 95% 1px 이하를 통과해야 배포됩니다.
- **한계:** 모두 합성 영상입니다. 실제 발 사진에서는 피부 질감, 스티커 재질, 카메라 처리 방식이 달라 성능이 다를 수 있습니다. 실제 사진에 정답 좌표를 표시한 회귀 세트가 필요합니다.

```
python3 bench/gen.py 10                                   # 개발용 생성
BENCH_OUT=holdout python3 bench/gen.py 10 100             # 보류 검증 세트
node bench/run.js src/core.js ALG-2.0                     # 평가
BENCH_DIR=holdout node bench/run.js test/legacy/core-1.1.js ALG-1.1   # 기존 엔진 비교
```

## v1.2 음성 안내 자가 검사 (손대지 않는 촬영)

1. 휴대폰을 **가로로 세워 두 발 사이 바닥**에 두고, 뒷면 카메라가 검사할 발 안쪽을 향하게 합니다.
2. 시작을 누르면 음성 안내가 나옵니다. 발이 가이드(점선) 안에 1초 동안 안정적으로 들어오면 **“찍습니다”** 하고 **앉은 자세(비체중부하)**를 연속 촬영합니다.
3. “일어서세요” 안내 뒤 일어서는 움직임을 감지하고, 다시 1.5초 동안 안정되면 **“찍습니다”** 하고 **선 자세(체중부하)**를 찍습니다.
4. 전·후 스티커 크기로 휴대폰이 움직였는지 확인합니다. 움직였으면 처음부터 다시 찍습니다.
5. 양발 모드에서는 왼발이 끝나면 휴대폰을 돌려 오른발을 이어서 검사합니다.

결과 화면의 **유연성 평발 자가 확인**은 다음을 보여 줍니다.

- 앉음 → 섬 아치 높이와 하강량
- 연구 기준 분류와 유연성 평발 양상 안내
- 자가 확인 질문 2개(쉴 때도 아치가 없음, 통증·붓기): 하나라도 해당하면 이 검사로는 판단할 수 없어 전문가 상담을 안내합니다.

**관리** 탭에서는 발별 하강량 추이, 운동 횟수, 측정 오차를 고려한 변화 해석을 봅니다.

음성은 Web Speech API(ko-KR)를 씁니다. 음성을 지원하지 않는 브라우저에서는 화면 자막과 신호음으로 대신합니다.

## v1.1 트래킹 개선

- **Web Worker 분석:** 검출을 화면과 분리된 스레드에서 실행합니다. 지원하지 않는 환경에서는 메인 스레드로 자동 전환합니다.
- **ROI 추적:** 직전 프레임에서 찾은 스티커 주변만 검색하고, 놓치면 전체를 다시 검색합니다. 분석 속도가 약 3fps에서 약 15fps로 빨라졌습니다(테스트 환경 기준).
- **라벨 일관성 검사:** 프레임 사이에 P1·P2·P3가 뒤바뀌면 준비 상태를 해제합니다.
- **움직임 판정:** 최근 0.6초 동안 기준점의 최대 이동량(스티커 지름 대비)으로 판단합니다.
- **화면 떨림 보정:** 오버레이 표시만 부드럽게 하고, 측정에는 원래 좌표를 씁니다.
- **연속 촬영(버스트):** 12프레임을 찍은 뒤 흐린 프레임과 튀는 프레임(중앙값 ± 3·MAD)을 버리고, 남은 프레임의 좌표를 평균합니다. 사용한 프레임 수와 높이 SD(반복성)를 함께 기록합니다.

## 연구자 초기 설정

1. 설정 → 연구자·관리자 모드에서 PIN을 설정합니다.
2. 측정 알고리즘 보정 화면에서 스티커의 실제 지름(mm)을 저장합니다.
3. 템플릿을 100% 크기로 인쇄해 촬영하고, 검증을 통과시킵니다. 통과해야 mm 값과 분류가 표시됩니다.
4. 운동 콘텐츠 관리 화면에서 처방 수치와 영상을 입력하고, 분류별로 운동을 연결합니다.

## 개발과 테스트

```
node build.js            # src/ + public/ → dist/ (index.html, sw.js, manifest, icons)
node test/unit.test.js   # 단위 테스트 56개 (CI에서도 실행)
node test/e2e.js         # 브라우저 E2E 24개 (Playwright, 가상 카메라 영상 필요)
node test/e2e-self.js    # 음성 자가 검사 E2E 12개 (앉음→일어섬→섬 가상 영상)
node test/e2e-track.js   # 트래킹 강건성 E2E 6개 (방해물 등장·저조도 전환 가상 영상)
```

단위 테스트는 분류 경계값, 기하 계산, 합성 이미지 검출, mm 환산, 오차 지표, 보정, 트래킹을 다룹니다.

E2E 테스트를 돌리려면 먼저 가상 카메라 영상을 만드세요.

```
ffmpeg -loop 1 -i test/img/pre.png -t 4 -r 10 -pix_fmt yuv420p test/img/pre.y4m
cd test/img && ffmpeg -loop 1 -t 8 -i pre.png -loop 1 -t 2 -i nostickers.png -loop 1 -t 15 -i post.png \
  -filter_complex "[0:v][1:v][2:v]concat=n=3:v=1:a=0,fps=10,format=yuv420p" self.y4m
# track.y4m: pre.png 4초 → pre_distractor.png 4초 → pre_distractor_dim.png 8초 (같은 방식으로 연결)
```

합성 이미지는 테스트 전용이며, 실제 측정 결과와 섞이지 않습니다.

## 아직 남은 한계

- 실제 발 사진으로 정확도를 검증하지 않았습니다. 검출 기준값은 초기 추정치입니다.
- 데이터는 기기 안(IndexedDB)에만 저장됩니다. 클라우드 동기화 기능은 없습니다.
- NDT 기준의 바닥선 측정과 NDT 하강량 입력 화면은 다음 단계에서 구현할 예정입니다.
- 유연성 평발 판단은 본 연구 분류 기준을 따른 것이며, 경직성 평발은 자가 확인 질문으로만 걸러 냅니다.
